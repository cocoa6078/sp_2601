# RUNWAVE 動作確認ダッシュボード（frontend/dev-dashboard）

Windows のブラウザ（Edge / Chrome）で、RUNWAVE の **core の計算** と **バックエンド API** をつないで確かめるためのローカル画面です。
日本語 UI・Vite + 素の JavaScript / CSS。画面には常に「架空信号・固定歩幅によるシミュレーション（モデル上の推定値）」と表示されます。ケイデンスの単位は **歩/分**（心拍数ではありません）。

> これは Web による表示確認です。SwiftUI の表示・動作、Xcode ビルド、Watch 連携、実機動作の確認にはなりません。

## 必要なもの

- Node.js（開発時は v24 系で確認。Vite 6 の要件として 18 以上）
- ブラウザは前面のタブで開くこと（下の「既知の制約」参照）

## 起動と終了（Windows）

PowerShell で、リポジトリの `frontend\dev-dashboard` に移動して実行します。`npm` ではなく **`npm.cmd`** を使います。

```powershell
cd C:\Users\<あなた>\dev\sp_2601\frontend\dev-dashboard
npm.cmd install
npm.cmd run dev
```

ブラウザで **http://127.0.0.1:5173** を開きます（このアドレスでしか待ち受けないので、LAN からは見えません。5173 が使用中なら Vite が別のポートを表示します）。

- 終了: `npm.cmd run dev` を実行したターミナルで **Ctrl+C**
- ビルド: `npm.cmd run build`（`dist/` に出力。確認だけなら `npm.cmd run preview` で http://127.0.0.1:4173）
- テスト: `npm.cmd test`（`node --test "test/*.test.js"`。Vite なしで動きます）
- ルートの core / tools のテスト: リポジトリ直下で `npm.cmd test`

Vite が公開するのは、このフォルダと `core/` だけです（ドライブ全体は公開しません）。

## バックエンドを使うとき（任意）

固定シナリオはバックエンドが止まっていても動きます。API 確認をするときだけ、**別のターミナル**で起動します。

```powershell
cd C:\Users\<あなた>\dev\sp_2601\backend
npm.cmd install
node index.js
```

既定のポートは 3001 です（`http://localhost:3001`）。ダッシュボードの「4. API 接続確認」の URL 欄で変更できます。
起動時の既定 URL を変えたいときは環境変数 `VITE_RUNWAVE_API_BASE` を使います。

```powershell
# その PowerShell だけ有効
$env:VITE_RUNWAVE_API_BASE = "http://localhost:3001"
npm.cmd run dev
```

または `frontend\dev-dashboard\.env.local` に 1 行書きます（`.gitignore` 済み）。

```
VITE_RUNWAVE_API_BASE=http://localhost:3001
```

環境変数を指定した場合は、画面で保存した URL（localStorage）よりこちらが優先されます。値を変えたら dev サーバーを再起動してください。
`tools/mock-server.js`（偽サーバー）も使えます: リポジトリ直下で `node tools/mock-server.js 8787` → URL 欄に `http://localhost:8787`。

## 固定モードと API モード

| | 固定モード（初期表示） | API モード |
|---|---|---|
| データの出所 | `core/scenarios.js` の固定シナリオ | バックエンド `GET /api/signals` の信号 1 件 |
| バックエンド | 不要 | 必要（別ターミナルで起動） |
| 切り替え | 「1. シナリオ」のボタン | 「4. API」で信号を選び **「比較条件へ適用」** を押したときだけ |
| 戻す | - | 「固定シナリオに戻す」（ユーザー操作のみ） |

- API の信号を受信しただけでは、固定シナリオの条件は上書きされません。適用すると両レーンがリセットされます。
- API の `crossingM` は **横断幅**として `signal.crossingM` に入ります。スタートから横断地点までの距離 `route.crossingX` には入りません（歩幅・通常ケイデンスなども固定側の値のままです）。
- API が落ちているときは接続失敗として表示されます。黙って成功や実データ表示にはなりません。
- 確認は **GET のみ・ボタンを押したときだけ**（`/api/signals`、`/api/calibration`、`/api/logs`）。HTTP 200 でも、JSON でない・形式が不正・信号が空・本文のステータスが「成功」でない場合は「失敗」です。一部の信号だけ不正な場合は「成功＋警告」で、不正な件は選べません。
- 判定は 未確認 / 成功 / 失敗 の 3 種類です。HTTP が成功しても、機能全体や担当タスクの完了とは見なしません。

## 3 つの確認シナリオ

画面の「1. シナリオ」に並ぶ表は、**画面表示時に core の `compare()` を実行して算出した値**です（画面に固定値は書いていません）。参考として `core/CONTRACT.md`（core v0.2.0、Node v24.19.0）の比較表の値を引用します。

| シナリオ | 横断モデル | 通常: 停止回数/停止時間/総時間 | RUNWAVE: 停止回数/停止時間/総時間 | 見どころ |
|---|---|---|---|---|
| A（phaseS=20） | point | 1 回 / 20 s / 320.0 s | 0 回 / 0 s / 325.0 s | 減速して停止を回避。停止はなくなるが **5 秒遅い** |
| B（phaseS=100） | point | 1 回 / 60 s / 360.0 s | 0 回 / 0 s / 282.9 s | 加速して停止を回避し、約 77 秒早い |
| B（phaseS=100） | length（横断 20 m） | 1 回 / 60 s / 360.0 s | 1 回 / 60 s / 360.0 s | **回避できないケース** |

- point: 横断地点に着いた時刻の信号色だけで判定（青なら通過、青点滅・赤なら止まる）。
- length: 横断幅を渡り切れるだけの青が残っているときだけ進入。
- シナリオ一覧は `core/scenarios.js` の `SCENARIOS` と `DEMO` の**全キーから自動生成**します（ID は `A`、`DEMO.sub` のようにキー名。`DEMO.main` が `SCENARIOS.B` と同じオブジェクトなら重複を除きます）。上の表の 3 件に加えて `DEMO.sub`（phaseS=26）も出ます。`B-length` は B の length 版で、B があるときだけ作ります。core にシナリオが増えると、ボタンと期待値の表に自動で出ます。
- 結果の読み方は「停止回避」と「所要時間の差」を分けて表示します。遅くなったケースも「+5.0 秒・遅い」のままです。
- ゴール後に、画面の逐次 step の最終結果と `core.compare` の結果を項目ごとに照合し、「一致 / 不一致」を表示します。

### 操作

開始 / 一時停止 / 再開 / リセット / 1 ステップ（0.1 秒）/ 表示速度 1・2・5 倍。
表示速度が変えるのは「1 回の描画で何 tick 進めるか」だけで、core の刻み（dt）は常に 0.1 秒です。速度・一時停止を変えても最終結果は変わりません（テストで確認）。
設定の編集は停止中（未開始・一時停止・ゴール後）だけで、「適用してリセット」で両レーンを作り直します。不正な入力（空欄・数値でない・Infinity・負値・周期の不一致・core の検証エラー）は理由が表示され、直せば再開できます。

## 結果の共有

「5. 結果の共有」から出力します。

- **Markdown をコピー**: Clipboard API でコピー。使えない環境では、全選択済みの読み取り専用テキスト欄が開くので Ctrl+C でコピーします。
- **JSON をダウンロード**: `runwave-check_<シナリオ>_<時刻>.json`。

含まれるもの: 確認日時、環境（UserAgent・URL）、core バージョン、Git SHA、シナリオ ID、config 全体、データの出所、通常 / RUNWAVE の結果、逐次と `compare` の照合結果、API 確認結果、再現手順、メモ、未確認事項（自動で追記）。
ゴール前に出力すると「途中経過」として出力されます。

### Git SHA の扱い

Git SHA は、dev サーバー / ビルドの**起動時に `.git/HEAD` と参照先のファイルを読んで埋め込む静的な値**です（`git` コマンドは実行しません）。

- 読めなければ「不明」と記録します。
- **未コミット変更の有無は記録しません。** SHA だけで完全に再現できるとは限らないため、レポートの「未確認事項」にも書かれます。変更がある状態で共有するときは、メモ欄に変更内容を書いてください。
- dev サーバーの起動中にコミットしても SHA は更新されません。**コミット後は `npm.cmd run dev` を再起動**してください。

### 担当別チェック（手動記録）

「7. 担当別チェック」は、担当・項目・状態（未確認 / 確認中 / 成功 / 失敗）・証拠メモを人が記録する欄です。

- 初期状態はすべて「未確認」。Mac ビルドや実機動作を自動で成功にしません。
- 自動検査（照合・API 確認）の結果では更新されません。メモを書いても状態は変わりません。
- 保存先は **このブラウザの localStorage だけ**です（共有・送信はしません。別の PC には引き継がれません）。

## 端末風プレビュー（P1）

「6. 端末風プレビュー」は、比較シミュレーターと**同じ core state**（目標ケイデンス・モード・信号色と残り秒）を iPhone 風 / Watch 風のカードで表示します。別のタイマーや別の計算は持たず、シミュレーターの描画と一緒に更新されます。

- SwiftUI とは独立した Web プレビューです。実機の画面を再現するものではありません。
- 速度 m/s・実測ケイデンス 歩/分・心拍 拍/分を入力できます（それぞれ「欠測」チェック付き）。常に「模擬入力」と表示します。空欄・欠測は「未計測」（0 にはしません）。
- 「目標値」「core の推定値（速度 = 歩幅 × ケイデンス ÷ 60。待機中は 0 m/s）」「模擬実測値」を分けて表示します。ペースは 1000 ÷ 速度（分:秒/km）で、速度が 0 または未計測なら「算出不能」です。
- **模擬値は表示確認のみで、core には渡していません。** `CONTRACT-ext.md` は設計のみ（未実装・要合意）で、心拍の閾値判定や自動減速は実装していません。

## core が変わったとき

`git pull` などで `core/` が変わったら、**`npm.cmd run dev` を再起動**してください（Git SHA は起動時に読むため。コードの変更自体は Vite が即時に反映します）。

### 自動で画面に出るもの（ダッシュボードのコードを直さなくてよい）

- **シナリオ**: `SCENARIOS` / `DEMO` に足したものが、ボタンと `core.compare` の期待値の表に出ます（既知でない ID には「新規」バッジ）。
- **core の公開 export**: ページ下部「core の公開関数・export 一覧」に、全 export を「使用中 / 未使用」に分けて出します（関数は引数の数つき。ダッシュボードが把握していない名前は「新規の可能性」バッジ）。
- **core state の全項目**: 比較シミュレーターの下の折りたたみに、両レーンの現在の state を全キー（`history` 除く）で出します。ダッシュボードが意味を知らないキーには「新しい項目」バッジが付きます。
- **集計（summary）の新しい項目**: 画面の結果と共有レポートの「その他の集計」に出ます。ゴール後の「逐次 step と `compare` の照合」も、summary の**全キー**（入れ子・配列を含む）を比べます。
- **モード名**: core の `MODE_LABELS` を使います。新しいモードが `MODE_LABELS` に無ければ、生のモード値をそのまま表示します。
- **横断モデル**: `CROSSING_MODELS` に増えたものは選択肢に出ます（説明文がないモデルは、その旨を表示します）。
- **設定項目**: フォームにない設定（core の既定値やシナリオにあるもの）は、「編集欄にない設定」として一覧に出し、「適用してリセット」でも失わずに引き継ぎます（編集はできません）。

### 契約チェック（壊れたときの動き）

起動時に、ダッシュボードが使う export（`createRun` / `step` / `summarize` / `compare` / `signalAt` / `speedOf` / `validateConfig` ほか）と、state・summary の必須項目がそろっているかを確認します（`createRun` / `step` / `summarize` を 1 回ずつ実際に試します）。足りない場合は画面上部に**赤い帯**「core の契約が変わりました（不足: …）」を出し、**該当する機能だけ**を無効にします（比較シミュレーター / 設定の適用 / 端末風プレビュー / API 確認 / シナリオ選択）。残りの機能は使えます。`MODE_LABELS` や `CORE_VERSION` のような任意の export が無いだけなら、黄色の帯で知らせるだけです。致命的な例外が起きたときも、白画面にせずエラーを表示します。共有レポートの「未確認事項」にも不足が入ります。

### 自動では出ない・連動しないもの

- **SwiftUI / Xcode は連動しません**。core を変えても、iPhone / Watch アプリ側は別途ビルド・確認が必要です。
- **`step` の第 3 引数**（`CONTRACT-ext.md` の実測入力・ユーザー操作・制約）は、自動では渡しません。端末風プレビューの模擬センサー値も core には渡しません（表示確認のみ）。
- core の**関数が増えても、画面に新しい操作は自動では生えません**（一覧に出るだけです）。新しい関数を使う画面が必要なら、ダッシュボード側の実装が必要です。
- state・summary の**既存項目の意味が変わった**場合（単位の変更など）は検出できません。照合（逐次 = `compare`）が一致していても、意味の確認は担当に聞いてください。
- `core/runwave-core.js` などのファイル自体を消した・改名した場合は、読み込みに失敗して画面が出ません（名前空間で受けているのは export の増減だけです）。

## 対応する core 契約

- `core/runwave-core.js` **v0.2.0**（`core/CONTRACT.md`）。ダッシュボードは `createRun` / `step` / `summarize` / `compare` / `validateConfig` / `signalAt` / `speedOf` と、`core/api-adapter.js` の `extractSignals` / `extractRunner` / `unwrap`、`core/scenarios.js` を実ファイルのまま import します（コピーしていません）。
- core の dt は 0.1 秒固定、乱数なし。待機中は `bpm=0`。core v0.2.0 の `stopTimeS` は終了した待機の合計なので、画面は待機中に `t − stoppedAtT` を足して表示します。
- `core/CONTRACT-ext.md`（実測入力・ユーザー操作・優先順位）は**設計のみ**で、ダッシュボードは使っていません。
- 実装時は実ファイルを正とします。契約と実装に差を見つけたら、画面側で隠さず担当に伝えてください。

## 既知の制約

- **ブラウザのタブが非表示（別タブ・最小化・裏のウィンドウ）だと `requestAnimationFrame` が止まり、再生が進みません。** 前面で開いたままにしてください。「1 ステップ」ボタンは影響を受けません。
- 1 回の描画で進める実時間は 1 秒で頭打ちです（長く止まった後に一気に進まないため）。ブラウザが描画を 1 秒に 1 回程度へ絞る環境（省電力など）でも速度どおり進みますが、表示はカクつきます。結果には影響しません。
- length モデルなど停止を回避できないケースは計算が重く、ゴール後の照合（`compare` の再計算）に約 1 秒かかります。
- 最大時間は 1800 秒です。超えると「時間切れ」と表示します（到達不能とは断定しません）。
- localhost へ接続できないときの原因表示は、ブラウザ上では「サーバー停止・URL・ポート違い、または CORS の拒否」を区別できません。
