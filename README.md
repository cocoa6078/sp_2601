# RUNWAVE

**信号待ちで途切れるランニングのリズムを、少しの歩調調整でつなぐ。**

RUNWAVE は、信号の青の時間帯に合わせて目標ケイデンスを調整するランニング支援プロトタイプです。目指すのは、普段の走り方をなるべく保ちながら、停止によるリズムの中断を減らすことです。自分のリズムで走り続けられる感覚や、信号の直前に急ぐことを減らした心理的な快適さも、検証したい価値として位置づけています。

現在は、模擬経路・模擬信号で通常走行と RUNWAVE を比較する **Web シミュレーター**、仕組みを画面収録向けに見せる **発表用連動デモ**、参考信号などを返す **バックエンド API**、および **iPhone / Apple Watch アプリのソース**を開発しています。機能ごとの接続状況と確認範囲は「現在の実装範囲」を参照してください。表示する信号・結果はモデル上の推定値であり、実際の信号の点灯状況とは同期していません。

- Web シミュレーター: <https://jphacks.github.io/sp_2601/web-simulator/>
- 開発ダッシュボード: <https://jphacks.github.io/sp_2601/dev-dashboard/>

## 製品概要

### 背景（製品開発のきっかけ、課題等）

街中を走っていると、自分に合ったリズムができたところで信号待ちになり、止まってから再び走り出す場面があります。RUNWAVE は、この中断に着目しました。

信号の直前で急いだり立ち止まったりする代わりに、手前から少しずつ歩調を変えられたら、流れを保ったまま青の時間帯に到着できるかもしれない。その考えを、同じ条件での通常走行との比較によって確かめるプロジェクトです。

### 製品説明（具体的な製品の説明）

歩幅・通常ケイデンス・交差点までの距離・信号周期をもとに、青の時間帯に到着するための目標ケイデンスを計算します。BPM はここでは **歩/分（1 拍 = 1 歩）**を表し、心拍数とは別の値です。

Web では、地図上に開始地点・終了地点・経由点を置いて模擬経路を作り、通常走行と RUNWAVE を並べて再生できます。「経路確定」を押すと、置いた点を OpenStreetMap の道に沿った徒歩経路（OSRM）に置き換えます。固定デモは、信号 1 つの A/B/W と、5 つの交差点を続けて通る D を用意しています。経路はどれも道沿いの固定経路です。任意コースでも 2〜5 件の信号を連続して通過できます。地図の横には、iPhone アプリの走行中画面をブラウザ内で再現したパネルが並び、地図と同じ時刻の計算結果で動きます。実機が足りない場面でも、発表で案内の流れを見せられます。停止回数・停止時間・総所要時間や早歩きの状況を比較し、条件と結果を JSON に、0.1 秒ごとの時系列を CSV に保存できます。再生は 1 / 2 / 4 / 5 倍速で、倍率を変えても同じ模擬時刻の結果は一致します。詳細は [Web シミュレーターの README](frontend/web-simulator/README.md) を参照してください。

iPhone / Apple Watch 側には、歩幅・自然なケイデンスの校正、位置・歩数による走行計測、セッション結果表示、端末間通信、テンポ提示などのソース実装があります。iPhone シミュレーターの DEBUG ビルドには、デモ用の仮想信号と信号に応じた歩調ガイダンスもありますが、製品データ経路には接続されていません。**Web / core の信号計算から実機の案内までをつなぐ一連の連携は未完成で、これらの機能を実機で確認した記録もありません。**

発表用連動デモは、人物・入力・判定・スマホ／Watchの画面イメージをブラウザの1画面にまとめます。ブラウザ内で core を実行し、実 API・サーバー・実機には接続しません。詳細と起動手順は [発表用シミュレーターの README](frontend/presentation-simulator/README.md) を参照してください。

### 特長

#### 1. 普段の歩調に近い、小さな調整

通常ケイデンスの ±20 歩/分の範囲で、目標を 1 秒ごとに見直し、実際の歩調は 4 秒ごとに最大 2 歩/分ずつ変えます。青に到着できる候補のうち、通常ケイデンスとの差が小さいものを優先し、同じ差なら減速側を選びます。

このため、停止を減らせても総所要時間が長くなる場合があります。RUNWAVE では、所要時間とあわせて「どれだけ止まらずにつながったか」を見ます。選択規則は [core 契約](core/CONTRACT.md) と [計算実装](core/runwave-core.js) にまとめています。

#### 2. 青の時間帯に余裕を持って到着する

モデルでは青開始直後・青終了直前を避けた到着時間帯を設けます。現在の core の既定値は開始後 3 秒・終了前 8 秒です。固定デモ A/B/W は終了前 5 秒を明示しているため、条件を変えた結果とは区別します。

青点滅・赤での進入は止め、調整で通過できない場合は停止を推奨します。これらは模擬信号に対する計算上の判定であり、実際の横断可否を案内するものではありません。

#### 3. 必要な場面だけ、早歩きでつなぐ

走りの調整で余裕を持った青に到着できず、通常歩調での通過も難しいときは、時速 5.3〜5.8 km の早歩きを候補にします。それでも通過できない場合は停止を推奨します。早歩きは現在の core で既定有効です。

早歩きでは横断に必要な時間も計算し、渡り終えるまで歩きます。走りと早歩きの切り替えには、通常の「4 秒ごとに最大 2 歩/分」の制限とは別の規則があります。詳細は [早歩きフェーズの契約](core/CONTRACT.md) を参照してください。

### 解決できること

- 信号に合わせた歩調調整で、停止によるリズムの中断を減らせる条件を検討できる。
- 同じコース・信号条件で通常走行と比較し、停止時間と歩調の変化、所要時間の関係を確認できる。
- 走りの調整だけでは難しい場面で、早歩きを挟む選択を検証できる。

効果は信号周期・初期位相・距離・歩幅などの条件で変わります。固定シナリオや位相を変えた試験の結果は、そのモデル条件内の結果であり、実際の街中での停止回避率を示すものではありません。

### 今後の展望・優先して検証すること

任意コースの作成と複数信号の連続走行は、現在の Web で実装済みです。次は、そのモデル上の結果を実際の走行体験につなげるため、以下を優先します。いずれも今後の検証・開発項目であり、効果を実証済みという意味ではありません。

- **実走でのリズムと快適さの検証**：同じコースで通常走行と比較し、停止回数・停止時間・歩調の変動に加えて、テンポ調整や早歩きへの切り替えが負担にならないか、走者がリズムの継続や心理的な快適さを感じるかを確かめます。所要時間だけで価値を判断せず、実測と主観評価の両方で検証します。
- **歩行者信号データの精度と取得範囲の検証**：車両用データ由来の参考プリセットから実際の歩行者信号を扱う段階へ進むため、取得方法・点灯時刻との同期・予測誤差・地域ごとの利用可能範囲を確認します。欠損や古い情報も区別し、信頼できる情報がない場面の案内方法を設計します。
- **iPhone / Watch までの一連の連携**：Web / core の信号情報・目標ケイデンスを端末へ届け、案内、ユーザー操作、計測、結果確認までを実機で確かめます。実測の速度・ケイデンスを core に取り込む [拡張契約](core/CONTRACT-ext.md) は現在、設計案です。
- **信号情報がない場面での価値**：歩幅・自然なケイデンスの校正とテンポ提示の既存実装を出発点に、利用可能な信号情報がないコースでも、普段のリズムを保つ支援として役立つかを検証します。信号に合わせた調整と通常のテンポ案内を、利用者が区別できる体験にします。
- **実利用フローの検証**：発表用連動デモで実装済みの「入力→判定→端末表示」の説明に加え、iPhone / Watch の校正から開始、走行中の案内、終了後の結果までを実機でつなぎ、操作と模擬値・実測値の区別が理解できるかを確認します。

### 注力したこと（こだわり等）

- **普段のリズムを基準にすること**：速度を上げ続けるのではなく、通常歩調との差が小さい候補を選びます。
- **同条件で比較できること**：通常走行と RUNWAVE の差を制御 ON/OFF に揃え、固定 0.1 秒刻みの共通時計で進めます。
- **計算を一か所に集めること**：画面側で信号判断を作り直さず、単信号・複数信号とも共通 core の判断を使います。
- **デモ値と実測値を区別すること**：模擬経路、推定信号、未受信データを明示し、信号は色に加えて文字でも表示します。

## 開発技術

### 活用した技術

#### API・データ

- 自作の Express API：参考信号、経路に沿った信号の照合（along-route）、キャリブレーション、走行ログ、セッション案内の中継を提供します。公開デモ向けに、書き込みの禁止・入力値の検査・回数制限・書き込みトークンを入れています。[バックエンド実装](backend/index.js)・[API の説明](backend/README.md)
- JARTIC 由来の車両用信号データを加工した参考プリセット：デモ API の位相は仮に 15 秒ずつずらし、`isEstimated: true` を付けています。歩行者信号の実際の点灯情報ではありません。
- API なしで使える [模擬信号 fixture](frontend/web-simulator/src/fixtures.js)：固定デモとは別に、地図でのコース作成に使えます。
- OpenStreetMap の背景地図タイルと Leaflet：経路と信号の表示に利用します。
- [OSRM](https://routing.openstreetmap.de/about.html)（FOSSGIS 運営の公開サーバー、foot プロファイル）：任意コースの「経路確定」で 1 回だけ道沿いの徒歩経路を取得します。取得できないときは、置いた点を結ぶ直線に戻ります。固定デモの経路は、2026-10-18 に同じサーバーから 1 回取得して固定したもので、再生中は通信しません。利用条件（最大 1 リクエスト/秒、大量利用の禁止、帰属表示）に従い、地図に「経路: OSRM（FOSSGIS） © OpenStreetMap contributors」を表示します。OSM のデータに基づく推定経路であり、歩道・横断歩道を実際に通れるかは保証しません。

JARTIC のオープンデータは、[公式データ提供ページ](https://www.jartic.or.jp/service/opendata/) と [利用規約](https://www.jartic.or.jp/d/opendata/riyou_kiyaku.pdf) に従い、出典と加工した事実を明記します。リポジトリには JARTIC 由来との記録がありますが、**元データの正式なデータ種別・取得日・利用日・取得時点のファイル名は確認できません**。したがって、「交差点制御情報」等の特定カテゴリを使ったとは断定していません。実装では信号時間を F-02 形式へ変換し、青時間を 5 秒短縮して青点滅 5 秒を設定します。座標は別ファイルのスクレイピング結果で置き換える場合があり、札幌デモの位相は信号順に 15 秒ずつ、全件 API の位相は 0 秒に固定しています。これらは加工・仮定値で、歩行者信号の実測値ではありません。データ種別と利用日を確認したうえで、利用規約に沿った出典表記を確定してください。

### 独自技術

#### ハッカソンで開発した独自機能・技術

- [runwave-core.js](core/runwave-core.js)：歩調を徐々に変える過程を含めて到着を予測し、通常ケイデンスとの差が小さい目標を選択。早歩きへの切り替え、信号待ち、横断後の復帰、リズム指標も扱います。
- [route-core.js](core/route-core.js)：複数信号を、時刻・位置・ケイデンス・集計をリセットせず連続して計算します。判断対象は現在向かっている信号で、経路全体を一括で最適化する方式ではありません。[複数信号の契約](core/CONTRACT-route.md)
- [engine-adapter.js](frontend/web-simulator/src/engine-adapter.js)：単信号と複数信号の計算を画面から切り分け、逐次再生の結果と一括計算の一致を照合します。
- [route-geometry.js](frontend/web-simulator/src/route-geometry.js)：地図上の信号を模擬経路へ投影し、経路に沿った距離に変換します。横断地点の位置と横断歩道の長さを分けて扱います。
- [TempoOutputPlayer.swift](frontend/watch-app/Runwave%20watch%20Watch%20App/TempoOutputPlayer.swift)：受け取った目標ケイデンスに応じた、前景での振動・音のテンポ提示を実装しています。

## 開発者向け：起動方法

Node.js と npm、ブラウザを用意してください。既存の開発記録では Node.js 24 系を使用しています。以下はリポジトリ直下から実行します。Windows PowerShell では `npm` を `npm.cmd` に読み替えてください。

### Web シミュレーター（最初に試す場合）

```sh
cd frontend/web-simulator
npm install
npm run dev
```

ブラウザで `http://127.0.0.1:5174/` を開き、「再生」を押すと固定デモ B が動きます。複数の信号を続けて通る様子は、固定デモ D で見られます。バックエンドの起動は不要です。背景地図タイルと任意コースの道沿い経路の取得には、ネットワークを使います。

### バックエンド（API を使う場合）

別のターミナルで起動します。

```sh
cd backend
npm install
npm start
```

既定は `http://localhost:3001`。Web の「API」でこの URL を指定して参考信号や校正値を取得します。Web の結果保存はローカル JSON ダウンロードであり、`POST /api/logs` には自動送信しません。

主な環境変数:

| 変数 | 既定 | 内容 |
| --- | --- | --- |
| `PORT` | `3001` | 待ち受けポート |
| `DEMO_READONLY` | 手元では無効、Vercel では有効 | `1` で書き込み禁止（校正値の保存・ログの読み書き・案内の中継が 403 `READ_ONLY`）。Vercel で解除するときだけ `0` |
| `CORS_ORIGINS` | なし（全オリジン許可） | カンマ区切りで許可するオリジンを絞る |
| `RUNWAVE_LOGS_FILE` | `backend/logs.json`（Vercel は `/tmp/logs.json`） | 走行ログの保存先 |

Vercel ではログがインスタンスの入れ替わりで消えます。エンドポイントと応答の形は [バックエンドの README](backend/README.md) を参照してください。
