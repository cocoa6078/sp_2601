# RUNWAVE

**信号待ちで途切れるランニングのリズムを、少しの歩調調整でつなぐ。**

RUNWAVE は、信号の青の時間帯に合わせて目標ケイデンスを調整するランニング支援プロトタイプです。目指すのは、普段の走り方をなるべく保ちながら、停止によるリズムの中断を減らすことです。

現在の中心機能は、**模擬経路・模擬信号による Web シミュレーター**です。表示する結果はモデル上の推定値であり、実際の信号の点灯状況とは同期していません。

## 製品概要

### 背景（製品開発のきっかけ、課題等）

街中を走っていると、自分に合ったリズムができたところで信号待ちになり、止まってから再び走り出す場面があります。RUNWAVE は、この中断に着目しました。

信号の直前で急いだり立ち止まったりする代わりに、手前から少しずつ歩調を変えられたら、流れを保ったまま青の時間帯に到着できるかもしれない。その考えを、同じ条件での通常走行との比較によって確かめるプロジェクトです。

### 製品説明（具体的な製品の説明）

歩幅・通常ケイデンス・交差点までの距離・信号周期をもとに、青の時間帯に到着するための目標ケイデンスを計算します。BPM はここでは **歩/分（1 拍 = 1 歩）**を表し、心拍数とは別の値です。

Web では、地図上に開始地点・終了地点・経由点を置いて模擬経路を作り、通常走行と RUNWAVE を並べて再生できます。固定デモ A/B/W に加え、任意コースでは 2〜5 件の信号を連続して通過するシミュレーションに対応しています。停止回数・停止時間・総所要時間や早歩きの状況を比較し、条件と結果を JSON に保存できます。詳細は [Web シミュレーターの README](frontend/web-simulator/README.md) を参照してください。

iPhone / Apple Watch 側には、目標ケイデンスの設定・端末間通信・テンポ提示などのソース実装があります。**Web の信号計算から端末の案内までをつなぐ一連の連携は未完成**です。各部分の実装状況は後述します。

### 特長

#### 1. 普段の歩調に近い、小さな調整

通常ケイデンスの ±20 歩/分の範囲で、目標を 1 秒ごとに見直し、実際の歩調は 4 秒ごとに最大 2 歩/分ずつ変えます。青に到着できる候補のうち、通常ケイデンスとの差が小さいものを優先し、同じ差なら減速側を選びます。

このため、停止を減らせても総所要時間が長くなる場合があります。RUNWAVE では、所要時間とあわせて「どれだけ止まらずにつながったか」を見ます。選択規則は [core 契約](core/CONTRACT.md) と [計算実装](core/runwave-core.js) にまとめています。

#### 2. 青の時間帯に余裕を持って到着する

モデルでは青開始直後・青終了直前を避けた到着時間帯を設けます。現在の core の既定値は開始後 3 秒・終了前 8 秒です。固定デモ A/B/W は終了前 5 秒を明示しているため、条件を変えた結果とは区別します。

青点滅・赤での進入は止め、調整で通過できない場合は停止を推奨します。これらは模擬信号に対する計算上の判定であり、実際の横断可否を案内するものではありません。

#### 3. 必要な場面だけ、早歩きでつなぐ

走りの調整で余裕を持った青に到着できず、通常歩調での通過も難しいときは、時速 5.3〜5.8 km の早歩きを候補にします。それでも通過できない場合は停止を推奨します。早歩きは現在の core で既定有効です。

早歩きでは横断に必要な時間も計算し、渡り終えるまで歩きます。走りと早歩きの切り替えには、通常の「4 秒ごとに最大 2 歩/分」の制限とは別の規則があります。詳細は [早歩きフェーズの契約](core/CONTRACT.md) を参照してください。

### 解決できること

- 信号に合わせた歩調調整で、停止によるリズムの中断を減らせる条件を検討できる。
- 同じコース・信号条件で通常走行と比較し、停止時間と歩調の変化、所要時間の関係を確認できる。
- 走りの調整だけでは難しい場面で、早歩きを挟む選択を検証できる。

効果は信号周期・初期位相・距離・歩幅などの条件で変わります。固定シナリオや位相を変えた試験の結果は、そのモデル条件内の結果であり、実際の街中での停止回避率を示すものではありません。

### 今後の展望

- Web / core から iPhone / Watch への信号情報・目標ケイデンスの連携を完成させる。
- 実測の速度・ケイデンスやユーザー操作を core に取り込む。[拡張契約](core/CONTRACT-ext.md) は現在、設計案です。
- 実際の歩行者信号の情報を扱うための取得方法・時刻同期・精度を検証する。
- 実機・実走で、歩調の変化の受け入れやすさや早歩きへの切り替えを確かめる。

### 注力したこと（こだわり等）

- **普段のリズムを基準にすること**：速度を上げ続けるのではなく、通常歩調との差が小さい候補を選びます。
- **同条件で比較できること**：通常走行と RUNWAVE の差を制御 ON/OFF に揃え、固定 0.1 秒刻みの共通時計で進めます。
- **計算を一か所に集めること**：画面側で信号判断を作り直さず、単信号・複数信号とも共通 core の判断を使います。
- **デモ値と実測値を区別すること**：模擬経路、推定信号、未受信データを明示し、信号は色に加えて文字でも表示します。

## 開発技術

### 活用した技術

#### API・データ

- 自作の Express API：参考信号、キャリブレーション、走行ログを提供します。[バックエンド実装](backend/index.js)
- JARTIC 由来の車両用信号データを加工した参考プリセット：デモ API の位相は仮に 15 秒ずつずらし、`isEstimated: true` を付けています。歩行者信号の実際の点灯情報ではありません。
- API なしで使える [模擬信号 fixture](frontend/web-simulator/src/fixtures.js)：固定デモとは別に、地図でのコース作成に使えます。
- OpenStreetMap の背景地図タイルと Leaflet：経路と信号の表示に利用します。経路は指定点を結ぶ折れ線であり、歩道の通行可能性や実際の道路距離を保証する経路探索ではありません。

#### フレームワーク・ライブラリ・モジュール

| 領域 | 技術 |
| --- | --- |
| 計算 core | JavaScript ES Modules、Node.js 標準テストランナー |
| Web / 開発ダッシュボード | Vite、JavaScript、HTML / CSS、Leaflet（Web） |
| バックエンド | Node.js、Express、cors、ローカル JSON ファイルによるログ保存 |
| iPhone / Watch | SwiftUI、WatchConnectivity、MapKit、CoreMotion、CoreLocation、WatchKit、AVFoundation |

#### デバイス

- PC / Mac のブラウザ：シミュレーションと比較表示。
- iPhone：歩幅・自然なケイデンスの校正、終了地点の設定、セッション UI、Watch への目標値送信。
- Apple Watch：目標ケイデンスの表示と、振動または音によるテンポ提示。現在の出力処理は前景でのデモ用です。

### 独自技術

#### ハッカソンで開発した独自機能・技術

- [runwave-core.js](core/runwave-core.js)：歩調を徐々に変える過程を含めて到着を予測し、通常ケイデンスとの差が小さい目標を選択。早歩きへの切り替え、信号待ち、横断後の復帰、リズム指標も扱います。
- [route-core.js](core/route-core.js)：複数信号を、時刻・位置・ケイデンス・集計をリセットせず連続して計算します。判断対象は現在向かっている信号で、経路全体を一括で最適化する方式ではありません。[複数信号の契約](core/CONTRACT-route.md)
- [engine-adapter.js](frontend/web-simulator/src/engine-adapter.js)：単信号と複数信号の計算を画面から切り分け、逐次再生の結果と一括計算の一致を照合します。
- [route-geometry.js](frontend/web-simulator/src/route-geometry.js)：地図上の信号を模擬経路へ投影し、経路に沿った距離に変換します。横断地点の位置と横断歩道の長さを分けて扱います。
- [TempoOutputPlayer.swift](frontend/watch-app/Runwave%20watch%20Watch%20App/TempoOutputPlayer.swift)：受け取った目標ケイデンスに応じた、前景での振動・音のテンポ提示を実装しています。

## 開発者向け：起動方法

Node.js と npm、ブラウザを用意してください。既存の開発記録では Node.js 24 系を使用しています。以下はリポジトリ直下から実行します。Windows PowerShell では `npm` を `npm.cmd` に読み替えてください。

### Web シミュレーター（最初に試す場合）

```sh
cd frontend/web-simulator
npm install
npm run dev
```

ブラウザで `http://127.0.0.1:5174/` を開き、「再生」を押すと固定デモ B が動きます。バックエンドの起動は不要です。背景地図タイルの取得にはネットワークを使います。

### バックエンド（API を使う場合）

別のターミナルで起動します。

```sh
cd backend
npm install
npm start
```

既定は `http://localhost:3001`。Web の「API」でこの URL を指定して参考信号や校正値を取得します。Web の結果保存はローカル JSON ダウンロードであり、`POST /api/logs` には自動送信しません。

### 開発ダッシュボード

```sh
cd frontend/dev-dashboard
npm install
npm run dev
```

`http://127.0.0.1:5173` で core / API の確認や共有用レポート作成ができます。[詳しい手順](frontend/dev-dashboard/README.md)

### iPhone / Apple Watch

Mac の Xcode で [Runwave.xcodeproj](frontend/watch-app/Runwave.xcodeproj/) を開きます。対象ターゲット・署名・権限・ペアリングを確認してビルドしてください。Windows でのソース確認や Web の動作確認は、SwiftUI のビルド・端末間通信の実機確認を兼ねません。[Mac 側の確認事項](frontend/iP実装メモ.md)

### テスト・ビルド

各コマンドは表のディレクトリで実行します。Web / ダッシュボードのビルド前には、そのディレクトリで `npm install` が必要です。

| ディレクトリ | コマンド | 対象 |
| --- | --- | --- |
| リポジトリ直下 | `npm test` | core / tools のテスト |
| リポジトリ直下 | `npm run scenarios` | 固定条件での比較結果 |
| リポジトリ直下 | `npm run api-check -- http://localhost:3001` | 起動済み API の確認 |
| `frontend/web-simulator` | `npm test` / `npm run build` | Web のテスト / 配布用ビルド |
| `frontend/dev-dashboard` | `npm test` / `npm run build` | ダッシュボードのテスト / 配布用ビルド |

バックエンド単体の `npm test` は未整備です。上記は実行手順であり、この README の作成時にアプリ全体のテストや実機試験を実行したことを示すものではありません。
